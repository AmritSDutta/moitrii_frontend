# Architecture

Moitrii follows a decoupled **frontend + backend** architecture: a pure React 18 Single Page Application (SPA) bundled with Vite and routed with `react-router-dom`, and a Convex Cloud realtime backend handling authentication, database transactions, file storage CDN, and scheduled agent execution.

## High-Level Data Flow

```
User Interaction / Browser
  │
  ▼
React 18 + Vite SPA (src/pages/, react-router-dom)
  │  useQuery / useMutation
  ▼
Convex Cloud Realtime Backend (convex/) [brazen-rook-983]
  ├── Schema & Database      (convex/schema.ts)
  ├── Auth (Google OAuth)    (convex/auth.ts)
  ├── File Storage CDN       (convex/files.ts)
  ├── Content, Agents, Users (convex/*.ts)
  ├── Newsletter Engine      (convex/emails/brevo.ts)
  ├── Autonomous Crons       (convex/crons.ts)
  │     │ triggers hourly (:30 UTC)
  │     ▼
  ├── Agent Runner Action    (convex/agentRunner.ts)
  │     │ executes @convex-dev/workflow durable steps
  │     ▼
  ├── Modular AI Engine      (convex/ai/)
  │     ├── prompts.ts       (System prompt template & dynamic date injection)
  │     ├── tools/           (Convex Agent tools barrel & Firecrawl search)
  │     ├── reuseEngine.ts   (Search reuse check)
  │     ├── synthesizer.ts   (500+ word multilingual EN/BN/HI guide synthesis)
  │     ├── imagegen.ts      (16:9 infographic poster generation + _storage)
  │     ├── tts.ts           (Sarvam Bulbul v3 TTS primary + OpenAI + _storage)
  │     ├── research.ts      (YouTube video companion discovery)
  │     └── agentMail.ts     (Personal Agent update dispatch)
  └── HTTP Router Webhook    (convex/http.ts)
```

## System Components

### Frontend (React 18 + Vite SPA)

All UI lives under `src/pages/` and `src/components/` using `react-router-dom` for client-side routing. Key patterns:

- **React Router Navigation** (`src/App.tsx`, `src/pages/`) provides instant, zero-reload navigation between all 6 core screens and 404 fallback.
- **Convex Client Provider** (`src/components/ConvexClientProvider.tsx`) wraps the app with `ConvexAuthProvider` from `@convex-dev/auth/react` and `ConvexReactClient`.
- **AuthGuard** (`src/components/AuthGuard.tsx`) wraps member-only routes (`/dashboard`, `/requests`, `/onboarding`, `/publisher`), automatically prompting Google OAuth sign-in when unauthenticated.
- **Persistent Navbar Navigation** (`src/components/Navbar.tsx`) ensures Sign In, topic links, and member navigation remain visible across mobile, tablet, and desktop viewports.
- **useBrandAssets** hook dynamically resolves logo and hero image URLs from Convex File Storage CDN, with local fallback.

### Backend (Convex Cloud)

All backend logic lives in `convex/`. Every function is a serializable, type-safe transaction.

| File / Subsystem | Responsibility |
|------|---------------|
| `schema.ts` | Defines all tables (`users`, `agents`, `userInterests`, `requests`, `content`, `subscribers`) with validators, indexes, and full-text search |
| `auth.ts` | Configures `@convex-dev/auth` with Google as the sole provider |
| `http.ts` | Sets up the HTTP router and mounts auth routes |
| `files.ts` | Serves static brand assets (logo, hero) via Convex CDN |
| `content.ts` | Content queries (list, search, by-slug), publish mutation, and internal guide publishing |
| `agents.ts` | Agent state query, auto-initialization with `Moitrii Companion` persona, and schedule updates |
| `requests.ts` | User request queue, `isActive` user validation, and lifecycle management |
| `users.ts` | Viewer resolution, interests queries/mutations, preferred language updates, and `setUserActiveStatus` |
| `subscribers.ts` | Weekly digest newsletter subscription, one-click unsubscribe, active subscriber list, and top 10 digest dispatcher |
| `userDigests.ts` | Daily user personalized category digest orchestrator (collects last 24h articles, filters top 5 per user-opted category, and dispatches via Brevo) |
| `emails/brevo.ts` | Brevo REST integration for subscriber welcome confirmations, weekly top 10 digests, and daily category-filtered user digests |
| `ai/prompts.ts` | Extracted editorial system prompt template with `{CURRENT_DATE}` and language directives |
| `ai/tools/` | Convex AI Agent tools barrel (`firecrawl.ts` with `firecrawlSearchTool` and `firecrawlToolDefinition`) |
| `ai/reuseEngine.ts` | Full-text search and keyword similarity engine for knowledge reuse |
| `ai/synthesizer.ts` | Multilingual editorial guide synthesis via `gpt-5.6-luna` (English, Bengali, Hindi) with citations and 500+ word depth |
| `ai/imagegen.ts` | Dynamic 16:9 horizontal pictorial infographic poster generation + Convex File Storage upload |
| `ai/tts.ts` | Sarvam AI Bulbul v3 primary TTS with 2-attempt retry loop, OpenAI TTS fallback, and offline WAV persistence |
| `ai/research.ts` | YouTube lifestyle video discovery and embed linking |
| `ai/agentMail.ts` | HTML email rendering and delivery from dedicated `agent.email` inboxes |
| `agentRunner.ts` | Autonomous wake scheduler action & `@convex-dev/workflow` orchestrator |
| `crons.ts` | Recurring crons: hourly agent wake cycle, Sunday top 10 digest broadcast, daily user category digest (07:30 AM IST), and 24h retention cleanup |

### Triple-Channel Email Architecture

1. **Pipeline 1: Weekly Subscriber Digest (`convex/subscribers.ts` + `convex/emails/brevo.ts`):**
   - Dispatches every Sunday at 12:00 UTC (17:30 IST) to `subscribers` table via Brevo.
   - Features top 10 lifestyle articles ordered by `reusedCount` with 0 LLM token cost.
2. **Pipeline 2: Daily Agent Wake Deliverable (`convex/agentRunner.ts` + `convex/ai/agentMail.ts`):**
   - Dispatches when a user's dedicated companion wakes and completes research on queued requests.
   - Delivered directly from the user's dedicated agent virtual inbox (`agent-<userId>@agentmail.to`) to their personal email with audio and video badges.
3. **Pipeline 3: Daily User Personalized Category Digest (`convex/userDigests.ts` + `convex/emails/brevo.ts`):**
   - Dispatches daily at 02:00 UTC (07:30 AM IST) via Brevo.
   - Collects articles published in the last 24 hours and delivers up to top 5 articles per user-selected preference category. Skips users with 0 new 24h articles.

### Security, Privacy & PII Boundary

- **PII Isolation:** Real human names and personal emails exist strictly in the `users` table. The `agents` table stores companion persona names (`"Moitrii Companion"`) and virtual AgentMail addresses (`agent-...@agentmail.to`). All downstream tables (`requests`, `content`, `userInterests`) reference only opaque `userId` keys.
- **Dispute & Moderation Safety:** `users.isActive` defaults to `true`. If set to `false`, agent wake evaluation, request creation, and profile modifications are blocked immediately.
