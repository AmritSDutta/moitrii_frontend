# Data Model

The Convex schema is defined in `convex/schema.ts`. It extends the built-in `authTables` from `@convex-dev/auth` and adds six application tables.

## Tables Overview

| Table | Purpose |
|-------|---------|
| `users` | Auth user profiles (extended from `@convex-dev/auth`) |
| `agents` | Persistent per-user agent state (status, schedule) |
| `userInterests` | User-selected topic subscriptions |
| `requests` | Research requests with lifecycle status |
| `content` | Published guides/articles in the shared knowledge library |
| `subscribers` | Weekly curated lifestyle digest email subscribers |

## Table: users

Extended from `@convex-dev/auth` with dispute moderation and language preferences.

```ts
// users table (managed by @convex-dev/auth + extended by Moitrii)
users: defineTable({
  name: v.optional(v.string()),        // Sole location of human name
  email: v.optional(v.string()),       // Sole location of human email
  image: v.optional(v.string()),
  emailVerificationTime: v.optional(v.number()),
  phone: v.optional(v.string()),
  phoneVerificationTime: v.optional(v.number()),
  isAnonymous: v.optional(v.boolean()),
  preferredLanguage: v.optional(v.union(
    v.literal("en"),
    v.literal("bn"),
    v.literal("hi")
  )),
  isActive: v.optional(v.boolean()),   // Dispute safety flag (defaults to true)
})
  .index("email", ["email"])
```

## Table: agents

Stores the persistent state of each user's personal AI agent with virtual inbox identity.

```ts
agents: defineTable({
  userId: v.id("users"),           // FK → users
  name: v.optional(v.string()),    // Persona name: "Moitrii Companion"
  email: v.optional(v.string()),   // AgentMail inbox: agent-<userId>@agentmail.to
  status: v.union(
    v.literal("SLEEPING"),
    v.literal("ACTIVE"),
    v.literal("WORKING"),
    v.literal("WAITING"),
    v.literal("ERROR")
  ),
  statusMessage: v.string(),
  nextWakeTime: v.string(),
  lastActiveTime: v.string(),
  wakeFrequency: v.string(),
  wakeTimeOfDay: v.optional(v.string()), // 24h format in IST, e.g. "23:00"
  timezone: v.optional(v.string()),      // defaults to "Asia/Kolkata"
  subscriptionTier: v.string(),
  activeTask: v.optional(v.string()),
  lastRunAt: v.optional(v.string()),
})
  .index("by_user", ["userId"])
  .index("by_wake_time", ["wakeTimeOfDay"])
  .index("by_email", ["email"])
```

## Table: userInterests

Tracks which lifestyle topics each user has subscribed to.

```ts
userInterests: defineTable({
  userId: v.id("users"),
  topicIds: v.array(v.string()),
}).index("by_user", ["userId"])
```

## Table: requests

Durable research request queue. Status transitions: `PENDING` → `PROCESSING` → `COMPLETED` | `FAILED`.

```ts
requests: defineTable({
  userId: v.id("users"),
  prompt: v.string(),
  category: v.string(),
  status: v.union(
    v.literal("PENDING"),
    v.literal("PROCESSING"),
    v.literal("COMPLETED"),
    v.literal("FAILED")
  ),
  submittedAt: v.string(),
  scheduledFor: v.string(),
  completedAt: v.optional(v.string()),
  contentId: v.optional(v.string()),
  contentTitle: v.optional(v.string()),
  isReused: v.boolean(),
  reuseNote: v.optional(v.string()),
}).index("by_user", ["userId"])
  .index("by_status", ["status"])
```

## Table: content

Published articles/guides in the Shared Knowledge Ecosystem. Article body stored as `v.string()` for instant loading and native full-text search.

```ts
content: defineTable({
  title: v.string(),
  slug: v.string(),
  subtitle: v.string(),
  category: v.string(),
  author: v.string(),
  authorId: v.optional(v.id("users")),
  authorType: v.optional(v.union(v.literal("human"), v.literal("agent"))),
  readTime: v.string(),
  publishedAt: v.string(),
  coverImage: v.string(),
  coverImageStorageId: v.optional(v.id("_storage")),
  audioUrl: v.optional(v.string()),
  audioStorageId: v.optional(v.id("_storage")),
  reusedCount: v.number(),
  isReused: v.boolean(),
  takeaways: v.array(v.string()),
  content: v.string(),
  youtubeId: v.optional(v.string()),
  youtubeTitle: v.optional(v.string()),
  sources: v.array(v.object({ title: v.string(), url: v.string() })),
  generatedFromPrompt: v.optional(v.string()),
})
  .index("by_slug", ["slug"])
  .index("by_category", ["category"])
  .index("by_reused_count", ["reusedCount"])
  .searchIndex("search_content", {
    searchField: "content",
    filterFields: ["category"],
  })
```

## Table: subscribers

Stores weekly curated lifestyle digest email subscriptions for anonymous visitors and authenticated users.

```ts
subscribers: defineTable({
  email: v.string(),
  subscribedAt: v.string(),
  source: v.optional(v.string()),
  status: v.union(v.literal("ACTIVE"), v.literal("UNSUBSCRIBED")),
}).index("by_email", ["email"])
```

## Relationships

```
users
  └── (1:1) agents              via userId (agent name: "Moitrii Companion", email: agent-<userId>@agentmail.to)
  └── (1:1) userInterests       via userId
  └── (1:many) requests         via userId
  └── (1:many) content          via authorId (optional)

subscribers (standalone collection for anonymous & authenticated email recipients)
```

## Privacy & PII Boundary Invariants

To guarantee strict user privacy and seamless future anonymization:
1. **Zero Downstream PII:** Only the `users` table contains the human user's real name and personal email.
2. **Dedicated Agent Identity:** The `agents` table never copies human names or emails. It stores `name: "Moitrii Companion"` and a dedicated AgentMail address (`agent-<userId>@agentmail.to`).
3. **Opaque Foreign Keys:** All application records (`requests`, `content`, `userInterests`) link to users strictly through opaque `userId: v.id("users")`.
4. **Dispute Moderation (`users.isActive`):** When `isActive` is set to `false`, the platform immediately rejects new requests from the user and excludes their agent from scheduled wake cycles.

## Storage Decision

**Article body & takeaways** → stored in the Convex database document (`content: v.string()`) for:
- Instant reader latency (single reactive query)
- Native full-text search for content reuse matching
- Atomic 1-step publishing mutations

**Cover images & photos & TTS audio** → stored in Convex File Storage (`_storage`) with CDN delivery URLs, referenced via `coverImageStorageId` and `audioStorageId`.
