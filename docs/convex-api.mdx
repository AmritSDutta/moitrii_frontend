# Convex API Reference

All backend functions live in `convex/`. The frontend imports them via `api.<module>.<function>`.

## Auth

Configured in `convex/auth.ts` using Google as the sole OAuth provider. Routes are mounted in `convex/http.ts`.

## Files (`convex/files.ts`)

### `getBrandAssets` (query)

Returns CDN URLs for the brand logo and hero artwork, with fallback to local images.

**Args:** None

**Returns:** `{ logoUrl: string, heroUrl: string }`

## Users (`convex/users.ts`)

### `viewer` (query)

Returns the authenticated user document, or `null` if unauthenticated.

**Args:** None

**Returns:** User document | `null`

### `getInterests` (query)

Returns the authenticated user's selected topic IDs.

**Args:** None

**Args:**


Updates the user's preferred language for AI agent deliverables (English, Bengali, or Hindi).

**Args:**
```ts

```

**Returns:**
```ts
{
  success: boolean,
  preferredLanguage: "en" | "bn" | "hi"
}
```

**Args:**
```ts

```

**Returns:**
```ts
{

  isActive: boolean
}
```

**Args:**

## Content (`convex/content.ts`)

### `getPublishedContent` (query)

Lists published articles with optional category filtering and limit. Uses the compound index `by_category_and_reused_count` and `resolveCanonicalCategory` for $O(\text{limit})$ bounded index execution without full-table scans, ordered by popularity (`reusedCount` desc).

**Args:**
```ts
{
  category?: string,   // filter by topic ID (e.g. "cooking") or category title; "all" or omitted returns all
  limit?: number       // optional cap on results (e.g. 4 for Home Page)
}
```

**Returns:** `Array<ContentCard>`

### `getPaginatedContent` (query)

Returns a paginated list of published articles with total count metadata, page slicing, category filtering, and optional keyword search.

**Args:**
```ts
{
  category?: string,   // topic ID or category title
  page?: number,       // 1-indexed page number (default 1)
  pageSize?: number,   // items per page (default 12, max 48)
  search?: string      // optional keyword search
}
```

**Returns:**
```ts
{
  articles: Array<ContentCard>,
  totalCount: number,
  page: number,
  pageSize: number,
  totalPages: number,
  hasMore: boolean
}
```

### `getWhatsHot` (query)

Returns trending articles ordered by highest reuse count (`reusedCount`), querying directly against the `.index("by_reused_count")` index in descending order.

**Args:**
```ts
{ limit?: number }     // defaults to 4, clamped between 1 and 20
```

### `getContentBySlug` (query)

Retrieves a single article by its URL slug. Falls back to document ID lookup if the slug isn't a valid ID.

**Args:**
```ts
{ slug: string }
```

**Returns:** An explicit projection of the content document — card metadata, body, takeaways, sources and companion media — or `null`. The stored document is deliberately **not** returned, so `generatedFromPrompt` (the user's raw request text) and internal ids never reach the client.

### `generateUploadUrl` (mutation)

Generates a short-lived upload URL for direct image uploads to Convex File Storage.

**Args:** None

**Returns:** `string` (upload URL)

**Auth required.**

### `publishContent` (mutation)

Publishes a new guide to the Shared Knowledge Ecosystem. Features automatic slug sanitization (lowercasing, replacing spaces/special characters with hyphens) and duplicate slug collision resolution.

**Args:**

**Auth required.**

### `internalPublishGuide` (internal mutation)

Internal mutation used exclusively by the AI agent execution pipeline to atomically write research deliverables into the Shared Knowledge library.

### `checkContentReuse` (internal mutation)

Scores a user prompt against recently published guides in the same category and reuses one when it is a strong match, incrementing `reusedCount` rather than duplicating LLM generation.

Matching is **token overlap, not full-text search**. The score is recall over the prompt (`shared / |promptTokens|`), and a candidate must clear both gates before it is reused:

- `MIN_SHARED_TOKENS = 3` — an absolute floor, so two generic words such as "budget" and "hotels" can never match on their own.
- `REUSE_SIMILARITY_THRESHOLD = 0.5` — at least half of the prompt's meaningful tokens must appear in the candidate.

Candidates are tokenized with `/[^\p{L}\p{M}\p{N}\s]/gu`, which keeps letters and combining marks from any script so Devanagari and Bengali prompts tokenize correctly. (`\p{M}` matters: Indic vowel signs are Unicode marks, not letters, so a `\p{L}`-only class splits every Hindi/Bengali word into fragments.) A candidate is skipped unless its language matches the caller's.

**Args:**
```ts
{
  prompt: string,
  category?: string,
  language?: "en" | "bn" | "hi"   // defaults to "en"
}
```

**Returns:** `{ isReused: false }`, or `{ isReused: true, contentId, contentTitle, matchedSlug, reuseNote }`

## Agent Runner & Crons (`convex/agentRunner.ts`, `convex/crons.ts`)

### `convex/crons.ts` — Scheduled Jobs

1. **Hourly Autonomous Wake Cycle:**
```ts
crons.hourly(
  "autonomous-agent-wake-cycle",
  {},
  internal.agentRunner.triggerScheduledWakes,
  {}
);
```
Fires every hour using Convex's native `crons.hourly` helper without `minuteUTC`, allowing Convex to automatically select an off-peak minute and spread execution away from the top of the hour.

2. **Sunday Weekly Digest Broadcast:**
```ts
crons.weekly(
  "sunday-weekly-digest-broadcast",
  { dayOfWeek: "sunday", hourUTC: 12 },
  internal.subscribers.dispatchWeeklyDigestCron,
  {}
);
```
Delivers the top 10 guides of the week to all active subscribers every Sunday. Uses `crons.weekly` without `minuteUTC` to let Convex automatically select an off-peak minute.

3. **Daily Personalized User Digest:**
```ts
crons.daily(
  "daily-user-personalized-digest",
  { hourUTC: 2, minuteUTC: 0 },
  internal.userDigests.dispatchUserDailyDigestCron,
  {}
);
```
Delivers personalized top 5 articles per subscribed category published in the last 24 hours to registered users every morning (02:00 UTC / 07:30 AM IST).

4. **Daily Retention Cleanup:**
```ts
crons.interval(
  "daily-todo-retention-cleanup",
  { hours: 24 },
  internal.requests.cleanupExpiredRequests,
  {}
);
```

### `triggerScheduledWakes` (internal action)

The autonomous scheduler:

1. Calls `getDueAgentsWithRequests` with the current ISO timestamp.
2. Filters due agents to those with at least one `PENDING` request.
3. For each due agent, transitions agent → `WORKING` and requests → `PROCESSING`.
4. Executes the 6-step AI pipeline per request (see below).
5. On success: calls `completeAgentTask` → agent → `SLEEPING`, requests → `COMPLETED`, sends AgentMail notification.
6. On failure: calls `revertAgentWorking` → agent → `SLEEPING`, requests → `PENDING` (next cycle retries).

**Dispatch Window:** An agent is "due" when its scheduled `wakeTimeOfDay` (IST) falls within the last 60 minutes (`DISPATCH_WINDOW_MINUTES = 60`). This matches the hourly cron cadence — each agent fires once per 24h cycle.

### `getDueAgentsWithRequests` (internal query)

- Parses the current wall-clock time into IST minutes-since-midnight.
- Collects all `PENDING` requests, groups them by `userId`.
- For each user: loads their agent, skips inactive users (`users.isActive === false`), checks `isWakeDue(agent.wakeTimeOfDay, nowIstMinutes)`.
- Returns the due list with user info, agent identity, and queued request summaries.

### Pipeline Steps (orchestrated via `@convex-dev/workflow` per due agent)

1. **Content Reuse Check** (`checkContentReuse` internal mutation) — Language-scoped token-overlap match against published guides (3 shared meaningful tokens minimum, 0.5 prompt coverage, same language only). If a match exists, returns `{ isReused: true, contentId, contentTitle, reuseNote }`. The matched guide's `reusedCount` increments — this is the **social sharing signal** that powers "What's Hot".
2. **Web Grounding & Live Research** (`searchWebWithFirecrawl` / `firecrawlSearchTool`) — Live web search using Firecrawl API (`limit: 3`) with honest offline curated fallbacks.
3. **Multilingual Synthesis** (`researchAndSynthesizeStep`) — 500+ word deep guide generation in the user's preferred language (`en` / `bn` / `hi`) dynamically injecting `{CURRENT_DATE}`.
4. **16:9 Infographic Cover Generation** (`imageGenStep` / `generateAndSaveCoverImage`) — Generates 16:9 horizontal pictorial infographics with strict no-text and family-safe zero-vulgarity ethics, stored in Convex File Storage (`_storage`).
5. **Audio Narration** (`narrationStep` / `generateAndStoreAudioNarration`) — Sarvam AI Bulbul v3 primary TTS with 2-attempt retry loop, OpenAI `tts-1` fallback, and offline WAV persistence stored in Convex `_storage`.
6. **Video Discovery** (`discoverVideoCompanion`) — YouTube video matching by category and prompt keywords.
7. **Atomic Publish** (`internalPublishGuide`) — Writes the deliverable into the shared knowledge library with `coverImageStorageId` and `audioStorageId`; available for reuse by other agents.
8. **AgentMail Notification** (`notifyCompletionStep` / `sendAgentCompletionNotification`) — Rich HTML and plain-text research report dispatched from `agent-<userId>@agentmail.to` to the user's personal email.

| Tool / Action | Purpose |

### State-Management Mutations

| Mutation | Purpose |
|---|---|
| `markAgentWorking` | Sets agent → `WORKING`, requests → `PROCESSING`, records `lastRunAt` |
| `revertAgentWorking` | On failure: agent → `SLEEPING`, requests → `PENDING` |
| `completeAgentTask` | On success: requests → `COMPLETED`, agent → `SLEEPING`, records `lastActiveTime` |

### Instant Wake Execution (`force: true`)

Developers can trigger instantaneous wake execution for local testing and live demos:

```bash
npx convex run agentRunner:triggerScheduledWakes '{"force": true}'
```
