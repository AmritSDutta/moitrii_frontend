# Convex API Reference

All backend functions live in `convex/`. The frontend imports them via `api.<module>.<function>`.

## Auth

Configured in `convex/auth.ts` using Google as the sole OAuth provider. Routes are mounted in `convex/http.ts`.

## Files (`convex/files.ts`)

### `getBrandAssets` (query)

Returns CDN URLs for the brand logo and hero artwork, with fallback to local images.

**Args:** None

**Returns:** `{ logoUrl: string, heroUrl: string }`

## Users (`convex/users.ts`)

### `viewer` (query)

Returns the authenticated user document, or `null` if unauthenticated.

**Args:** None

**Returns:** User document | `null`

### `getInterests` (query)

Returns the authenticated user's selected topic IDs.

**Args:** None

**Returns:** `string[]` (empty array if unauthenticated or no interests set)

### `updateInterests` (mutation)

Creates or updates the authenticated user's topic subscriptions.

**Args:**
```ts
{ topicIds: string[] }
```

### `updatePreferredLanguage` (mutation)

Updates the user's preferred language for AI agent deliverables (English, Bengali, or Hindi).

**Args:**
```ts
{ language: "en" | "bn" | "hi" }
```

**Returns:**
```ts
{
  success: boolean,
  preferredLanguage: "en" | "bn" | "hi"
}
```

### `setUserActiveStatus` (internal mutation)

Admin and dispute moderation mutation to enable or disable a user account. Disabling a user halts scheduled agent wake evaluation and blocks new request submissions.

**Args:**
```ts
{
  userId: Id<"users">,
  isActive: boolean
}
```

**Returns:**
```ts
{
  success: boolean,
  userId: Id<"users">,
  isActive: boolean
}
```

## Agents (`convex/agents.ts`)

### `getAgentState` (query)

Returns the personal agent state for the authenticated user. Auto-initializes a default agent document on first login return.

**Args:** None

**Returns:** Agent document | default SLEEPING state object

### `initializeAgent` (mutation)

Ensures an agent record exists for the authenticated user.

**Args:**
```ts
{
  wakeFrequency?: string,
  subscriptionTier?: string
}
```

**Returns:** `Id<"agents">`

### `updateWakeSchedule` (mutation)

Updates the scheduled wake time for the authenticated user's agent. Enforces the calm-tech policy: wake time must fall strictly between **9:00 PM and 9:00 AM IST** (daytime hours 09:01–20:59 are rejected).

**Args:**
```ts
{
  wakeTimeOfDay: string,   // 24h format, e.g. "23:00"
  timezone?: string        // defaults to "Asia/Kolkata"
}
```

**Returns:**
```ts
{
  agentId: Id<"agents">,
  wakeTimeOfDay: string,
  wakeFrequency: string,
  nextWakeTime: string
}
```

## Requests (`convex/requests.ts`)

### `listUserRequests` (query)

Lists all research requests for the authenticated user, sorted by most recent.

**Args:** None

**Returns:** `Array<Doc<"requests">>`

### `createRequest` (mutation)

Creates a new research request in the agent's durable queue. Remains stored while the agent sleeps.

**Args:**
```ts
{
  prompt: string,
  category?: string,       // defaults to "General Wellness"
  scheduledFor?: string    // defaults to next wake window
}
```

**Returns:** `Id<"requests">`

**Request lifecycle:** `PENDING` → `PROCESSING` → `COMPLETED` | `FAILED`

## Content (`convex/content.ts`)

### `getPublishedContent` (query)

Lists published articles with optional category filtering and limit (capped at 50 results).

**Args:**
```ts
{
  category?: string,   // filter by category; "all" or omitted returns all
  limit?: number       // optional cap on results (capped at max 50)
}
```

**Returns:** `Array<Doc<"content">>`

### `getWhatsHot` (query)

Returns trending articles ordered by highest reuse count (`reusedCount`), querying directly against the `.index("by_reused_count")` index in descending order.

**Args:**
```ts
{ limit?: number }     // defaults to 4, clamped between 1 and 20
```

### `getContentBySlug` (query)

Retrieves a single article by its URL slug. Falls back to document ID lookup if the slug isn't a valid ID.

**Args:**
```ts
{ slug: string }
```

**Returns:** Content document | `null`

### `generateUploadUrl` (mutation)

Generates a short-lived upload URL for direct image uploads to Convex File Storage.

**Args:** None

**Returns:** `string` (upload URL)

**Auth required.**

### `publishContent` (mutation)

Publishes a new guide to the Shared Knowledge Ecosystem. Features automatic slug sanitization (lowercasing, replacing spaces/special characters with hyphens) and duplicate slug collision resolution.

**Args:**
```ts
{
  title: string,
  slug: string,
  subtitle: string,
  category: string,
  author: string,
  authorType?: "human" | "agent",
  readTime: string,
  coverImage: string,
  coverImageStorageId?: Id<"_storage">,
  audioUrl?: string,
  audioStorageId?: Id<"_storage">,
  reusedCount?: number,
  isReused?: boolean,
  takeaways: string[],
  content: string,
  youtubeId?: string,
  youtubeTitle?: string,
  sources: { title: string; url: string }[],
  generatedFromPrompt?: string
}
```

**Returns:** `{ contentId: Id<"content">, slug: string }`

**Auth required.**

### `internalPublishGuide` (internal mutation)

Internal mutation used exclusively by the AI agent execution pipeline to atomically write research deliverables into the Shared Knowledge library.

### `checkContentReuse` (internal query helper)

Performs full-text search against the `content` table to match user prompts with high-confidence existing guides, incrementing reuse counters rather than duplicating LLM generation.

## Subscribers (`convex/subscribers.ts`)

### `subscribeDigest` (mutation)

Subscribes an email address to the weekly curated lifestyle digest. Validates email format with RFC 5322 regex, ensures idempotency by checking for existing active subscriptions, and dispatches a Brevo welcome confirmation email asynchronously.

**Args:**
```ts
{
  email: string,
  source?: string   // defaults to "footer"
}
```

**Returns:**
```ts
{
  success: boolean,
  message: string
}
```

## Email Communications (`convex/emails/brevo.ts` & `convex/ai/agentMail.ts`)

### `sendSubscriberWelcomeEmail` (Brevo action)

Dispatches a warm, branded welcome email via Brevo REST API when a user subscribes to the Moitrii lifestyle newsletter.

### `sendWeeklyDigestBroadcast` (Brevo action)

Dispatches a curated weekly digest of top lifestyle stories to all active subscribers via Brevo batch broadcasting.

### `sendAgentCompletionNotification` (AgentMail action)

Dispatches a personalized HTML research report directly from the user's dedicated agent inbox (`agent-<userId>@agentmail.to`) to their personal email address upon wake completion.

## Agent Runner & Crons (`convex/agentRunner.ts`, `convex/crons.ts`)

### `triggerScheduledWakes` (internal action)

Triggered on an hourly schedule (at `:30` minute UTC to align with IST `:00` boundaries) by `convex/crons.ts`.
- Queries all agents due for execution that have `PENDING` research requests.
- Filters out inactive users (`users.isActive === false`) for dispute safety.
- Sets agent status to `WORKING` and requests to `PROCESSING`.
- Executes the native modular AI pipeline:
  1. Content Reuse Check (`convex/ai/reuseEngine.ts`)
  2. Multilingual Synthesis (`convex/ai/synthesizer.ts` in English, Bengali, or Hindi)
  3. Audio Narration (`convex/ai/tts.ts` saved to Convex `_storage`)
  4. Video Discovery (`convex/ai/research.ts` YouTube embeds)
  5. Personal Notification (`convex/ai/agentMail.ts` from `agent.email`)
  6. Atomic Publishing (`convex/content.ts` `internalPublishGuide`)
- **Failure Rollback:** If any unhandled pipeline error occurs, automatically rolls back: reverts the agent state to `SLEEPING` with an explanatory message and resets requests back to `PENDING` so tasks never become stuck.

### `POST /api/agent/complete` (HTTP endpoint)

Callback endpoint mounted in `convex/http.ts` for external agent backends to submit completed research deliverables.
- **Fail-Closed Security:** Rejects requests with `503 Service Unavailable` if `AGENT_SERVICE_SECRET` is not configured in the backend environment, and `401 Unauthorized` if the `Authorization: Bearer <secret>` or `x-agent-secret` header is invalid.
- **Runtime Payload Validation:** Parses and shape-checks the untrusted request body via `parseCompletionBody` (`agentId` string and `deliverables` array) before invoking the internal `completeAgentTask` mutation.
- Transitions requests to `COMPLETED` and resets agent state to `SLEEPING`.
